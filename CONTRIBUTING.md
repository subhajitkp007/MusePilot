# Contributing to MusePilot

Thank you for contributing to **MusePilot**! We follow strict Meta-inspired engineering practices to maintain deterministic quality, security, and maintainability.

## Development Setup

1. Clone the repository and initialize the virtual environment:
   ```bash
   make setup
   cp .env.example .env
   ```
2. Run the pre-flight health check:
   ```bash
   make health
   ```
3. Run the linter and unit test suite:
   ```bash
   make lint
   make test
   ```

## Architectural Invariants

1. **Zero-Coordinate Invariant:** Never emit, accept, or pass raw `[x, y]` coordinates in planner prompts or schemas. All UI interactions must reference a `target_mask_id` generated by SAM 3.1.
2. **DPI Scale Normalization:** Always translate frame pixel coordinates to logical OS points by dividing by `display_dpi_scale`.
3. **Closed-Loop Verification:** Every state-mutating action must be gated by the `SparkOpenVerifier` before advancing the DAG.
4. **Structured Telemetry & Redaction:** Use `musepilot.telemetry` for all logging and metrics; never use bare `print()` statements in library modules.

## Commit Message Convention

```text
<component>: <concise summary>

Evidence: <test or verification result>
Milestone: <M1-M9 / S1-S3>
```
